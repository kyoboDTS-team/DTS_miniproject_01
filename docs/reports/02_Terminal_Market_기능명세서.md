## 2. 요구사항 및 상세 기능 명세

### 2.1 시스템 공통 (SYS) 및 인증/회원 (AUTH)

| 기능 ID | 기능명 | 대상 권한 | 상세 기능 설명 | 예외 및 처리 기준 |
| :---: | :--- | :---: | :--- | :--- |
| **SYS-01** | 콘솔 메인 헤더 출력 | 전체 | 모든 화면 상단에 `[TERMINAL MARKET]`, 현재 로그인 계정 정보, `장바구니(수량)`를 표준화하여 출력 | 세션 상태에 따라 비회원/회원/관리자 정보 동적 분기 |
| **SYS-02** | 권한별 메뉴 라우팅 | 전체 | 사용자의 권한(`Guest`, `CUSTOMER`, `ADMIN`)에 따라 접근 가능한 메뉴만 선택지로 노출 | 미인가 메뉴 입력 시 경고 출력 후 재입력 유도 |
| **AUTH-01** | 신규 회원가입 | 비회원 | 이메일, 비밀번호, 이름, 휴대폰번호를 입력받아 `app_user`와 `customer`에 동시 등록 | • 이메일 형식 불일치 또는 기등록 이메일 중복 시 거절<br>• 비밀번호 규칙(8~20자, 영문대/소/숫자/특수문자 필수) 미달 시 거절 |
| **AUTH-02** | 로그인 | 비회원 | 이메일과 비밀번호를 입력받아 SHA-256 해시 검증 후 `LoginSession`에 인증 정보 적재 | • 이메일 불일치 또는 비밀번호 불일치 시 안내 메시지<br>• 비활성화(`is_active=false`) 계정 로그인 차단 |
| **AUTH-03** | 로그아웃 | 회원/관리자 | 현재 `LoginSession`의 모든 정보를 완전히 `null`로 초기화하고 비회원 메인으로 복귀 | 세션 소거 후 이전 사용자의 장바구니/프로필 잔존 방지 |

| :---: | :--- | :---: | :--- | :--- |

| **CUS-02** | 내 정보 수정 | 회원 | 비밀번호 확인 절차를 거친 후 이름과 연락처를 변경하고 세션 객체에 즉시 동기화 | 기존 비밀번호 불일치 시 수정 진입 차단, 이메일은 수정 불가 |

### 2.3 상품 및 계층형 카테고리 (PRD)

### 2.4 재고 및 시리얼 단품 관리 (STK, SER)

| 기능 ID | 기능명 | 대상 권한 | 상세 기능 설명 | 예외 및 처리 기준 |
| :---: | :--- | :---: | :--- | :--- |
| **STK-01** | 상품 수량 입고/조정 | 관리자 | 특정 상품의 재고 수량을 변경하고, 사유와 담당자 정보를 `stock_adjustment`에 영구 기록 | 음수 재고 결과가 나오는 비정상 차감 시도시 트랜잭션 롤백 |

| **SER-01** | 시리얼 개별 등록 | 관리자 | 시리얼 관리 상품에 대해 단품별 고유 S/N을 등록하고 `AVAILABLE` 상태 부여 | 중복 시리얼 번호 등록 시도시 UNIQUE 제약조건 위반 방어 |
| **SER-02** | 시리얼 자동 출고 배정 | 시스템 | 주문 결제 시 해당 상품의 `AVAILABLE` 시리얼을 주문 수량만큼 조회하여 `SOLD`로 전이 | 판매 가능 시리얼 수가 주문 수량보다 부족할 경우 주문 전체 롤백 |

## 3. 핵심 업무 규칙 (Business Rules)

```text
[ 주문 및 반품 상태 전이 다이어그램 ]
      주문 결제 체결                       반품 신청 완료
┌─────────────────────────┐          ┌─────────────────────────┐
│        CONFIRMED        │ ───────> │        RETURNED         │
│ (재고 차감, 시리얼 SOLD)│          │ (재고 환원, 시리얼 복구)│
└─────────────────────────┘          └─────────────────────────┘
            │                                     │
            └─────────> [중복 처리 불가] <────────┘
```

1. **외부 노출용 주문번호(`order_no`) 채번 규칙**:
   * 형식: `TM-YYYYMMDD-XXXXXXXX` (예: `TM-20260922-A8K3Q7P2`)
   * DB 내부 시퀀스 PK(`order_id`)는 보안상 외부에 일체 노출하지 않으며, 난수 기반의 유니크한 문자열 코드를 발행하여 비회원 주문 추적 키로 사용합니다.
2. **비밀번호 정책 (Password Policy)**:
   * 8자리 이상 20자리 이하의 길이.
   * 영문 대문자, 영문 소문자, 숫자, 특수문자(`!@#$%^&*`)를 각각 최소 1자 이상 반드시 포함.
   * DB에는 평문이 아닌 솔트(Salt) 기반 SHA-256 해시값으로만 영구 저장.
3. **시리얼 생명주기 및 재고 정합성 규칙**:
   * 시리얼 관리 상품(`requires_serial=true`)은 `AVAILABLE`(판매 가능) 상태의 단품만 주문에 매핑될 수 있습니다.
   * 주문 완료 시 `SOLD` 상태로 변경되며 `order_item_unit`에 매핑 로그가 기록됩니다.
   * 반품 시에는 해당 시리얼이 다시 `AVAILABLE`로 전환되어 다음 구매 고객에게 즉시 재판매가 가능해집니다.
4. **트랜잭션 무결성 원칙**:
   * 주문 결제, 주문 반품, 대량 CSV 임포트는 모든 단계가 성공해야만 영구 반영(`commit`)되며, 단 하나의 오류라도 발생하면 직전 상태로 완전히 원복(`rollback`)됩니다.
