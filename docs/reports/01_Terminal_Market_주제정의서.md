## 2. 기획 배경 및 필요성

### 2.1 기존 학습 미션의 한계
* 일반적인 교육 과정 및 미니프로젝트의 콘솔 프로그램은 단순한 단일 테이블 기반의 CRUD(Create, Read, Update, Delete) 수준에 머무르는 경우가 많습니다.
* 이는 실제 기업 현장에서 요구되는 복잡한 비즈니스 로직(예: 다중 품목 장바구니 결제, 데이터베이스 트랜잭션 원자성 보장, 단품별 고유 시리얼 번호 추적, 반품 시 재고 및 시리얼 상태 원복 등)을 경험하기에 부족합니다.

### 2.2 실무형 E-Commerce 풀사이클 구현의 필요성
* 온라인 쇼핑몰과 물류창고는 단순히 "재고 숫자"만 줄어드는 시스템이 아닙니다.
* 고가의 전자기기나 명품 등은 단품마다 부여되는 고유한 **시리얼 번호(Serial Number)**를 기반으로 출고와 반품이 추적되어야 하며, 누가 언제 어떤 사유로 재고를 조정했는지 **감사 로그(Audit Log)**가 남아야 합니다.
* 이에 따라 터미널 마켓은 GUI(웹 화면)가 없는 순수 콘솔 환경에서도, 실제 상용 엔터프라이즈 백엔드에 버금가는 **쇼핑몰 + 물류 ERP 시스템의 풀사이클**을 구축하고자 기획되었습니다.

## 3. 프로젝트 목적 및 핵심 목표

### 3.1 프로젝트 목적
Java의 객체지향 설계 원칙(OOP), MyBatis SQL 매핑 프레임워크, 그리고 PostgreSQL 관계형 데이터베이스를 유기적으로 결합하여, 실무 수준의 무결성과 확장성을 갖춘 커머스 시스템을 완성합니다.

### 3.2 핵심 개발 목표
1. **쇼핑 라이프사이클의 완결성 달성**:
   * `상품 탐색(카테고리/조건) → 장바구니 담기 → 단일 트랜잭션 주문 결제 → 주문 상세 추적 → 주문 전체 반품`으로 이어지는 유기적인 프로세스 구현.
2. **시리얼(단품) 단위의 고도화된 재고 관리**:
   * 일반 품목(수량 중심)과 고가 품목(시리얼 추적 필수)을 구분.
   * `product_unit` 엔티티를 통해 실제 출고된 시리얼 번호를 주문에 맵핑하고, 반품 시 해당 시리얼을 즉시 판매 가능(`AVAILABLE`) 상태로 자동 환원.
3. **데이터 무결성 및 트랜잭션 보장**:
   * 주문 결제 시 재고 차감, 시리얼 상태 전이(`AVAILABLE` → `SOLD`), 주문 및 주문 항목 생성 작업이 단 하나의 트랜잭션(`commit/rollback`) 내에서 원자적으로 처리되도록 보장.
4. **역할 기반의 권한 분리(RBAC)**:
   * `비회원(Guest)`, `일반 회원(Customer)`, `관리자(Admin)`의 접근 경로와 실행 권한을 엄격히 통제.
5. **관리자 백오피스 역량 강화**:
   * 실시간 재고 부족/품절 경고, 재고 입출고 감사 로그(`StockAdjustment`), 통합 매출 통계 대시보드, 대용량 CSV 임포트/익스포트 지원.

## 5. 핵심 서비스 범위 및 주요 특징

```text
[ 터미널 마켓 핵심 서비스 범위 ]
┌─────────────────────────────────────────────────────────────┐
│                       사용자 인터페이스                      │
│        (GuestMenu)          (MemberMenu)       (AdminMenu)   │
└──────────────┬───────────────────┬──────────────────┬───────┘
               │                   │                  │
┌──────────────▼───────────────────▼──────────────────▼───────┐
│                        핵심 도메인 로직                      │
│  [인증/회원]    [상품/카테고리]    [장바구니/주문]    [재고/시리얼/통계]│

                               │ (MyBatis 매퍼 & 트랜잭션)
```

### 5.1 쇼핑몰 전 영역의 풀사이클 구축
* 단편적인 CRUD가 아닌, 상품 탐색부터 장바구니 담기, 복수 품목 주문, 상세 내역 확인, 그리고 주문 취소/반품에 이르는 전체 라이프사이클을 매끄럽게 연결했습니다.

### 5.2 시리얼(단품) 추적 기반의 실물 물류 아키텍처
* 노트북, 스마트폰과 같이 제품마다 고유 번호가 있는 상품은 개별 시리얼(`product_unit`) 단위로 관리됩니다.
* 주문이 체결되면 판매 가능한 시리얼 번호가 자동으로 배정되고, 반품 시에는 해당 시리얼 번호가 정확히 판매 가능 상태로 복구됩니다.

### 5.3 엄격한 데이터 정합성 검증 엔진 탑재
* 상품 테이블의 총 재고 수량(`product.stock_quantity`)과 실제 보관 중인 판매 가능 시리얼 개수(`product_unit.unit_status = 'AVAILABLE'`) 간의 불일치를 실시간 감지하는 `SerialStockConsistency` 모듈을 제공합니다.

## 6. 기대 효과 및 차별점

1. **실무 수준의 백엔드 트랜잭션 감각 확보**:
   * 복수 테이블에 걸친 INSERT/UPDATE 작업을 수동 커밋(`autoCommit=false`) 기반의 트랜잭션으로 제어하여 데이터 정합성 유지 능력을 입증했습니다.
2. **계층형 아키텍처(Layered Architecture)를 통한 높은 유지보수성**:
   * 콘솔 UI(`Menu`), 업무 규칙(`Service`), 데이터 접근(`DAO/Mapper`), 도메인 엔티티(`Model`)를 엄격히 분리하여 향후 웹/모바일 API 서버로의 전환이 용이합니다.
3. **디자인 패턴 기반의 견고한 인프라 구축**:
   * `DbConnectionFactory`를 통한 팩토리 패턴(Factory Pattern) 적용으로 DB 세션 생성의 책임을 캡슐화하고, `LoginSession`을 통한 싱글톤(Singleton) 세션 상태 관리를 달성했습니다.
