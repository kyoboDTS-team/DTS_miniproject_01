## 책임 경계
- Menu: 콘솔 입출력과 메뉴 이동.
- Service: 업무 규칙, 권한, 트랜잭션, 여러 DAO 조합.
- DAO: SQL 실행과 객체 변환. 임의 commit/rollback 금지.
- Cart: DB와 분리된 세션 상태.

## 주요 호출 흐름
### 회원가입
`SignupMenu → AuthService.signUp → AppUserDao + CustomerDao → commit`

### 장바구니
`ProductMenu → CartService.add → Cart`이며 DB 저장은 하지 않는다. 구매 시점에 OrderCommandService가 DB의 최신 가격·상태·재고를 다시 확인한다.

### 주문
`CartMenu → OrderCommandService.checkout → OrderCommandDao + ProductDao + ProductUnitDao → commit`

### 반품
`OrderCommandService.returnOrder → OrderCommandDao(status 조건부 변경) + ProductDao(재고 복구) + ProductUnitDao(시리얼 복구) → commit`

## 업무 분담 초안
| 담당 | 주 담당 | 공동 검토 |
|---|---|---|
| A | 상품·카테고리·재고·시리얼 | D와 주문 시 재고/시리얼 배정 |
| B | 회원가입 화면·고객 관리·장바구니 | D와 AuthService, C와 메뉴 연결 |
| C | 역할별 메뉴·주문 조회·통계·CSV | B와 장바구니 화면, D와 주문 조회 모델 |
| D | 로그인·권한·주문 생성·반품·트랜잭션 | A와 재고, B와 회원가입 |

보류 기능은 담당자를 지정하지 않는다. 확정 후 작업 카드로 추가한다.
