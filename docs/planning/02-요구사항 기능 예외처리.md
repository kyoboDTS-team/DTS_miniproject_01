## 비밀번호 정책
- 길이: 8~20자
- 영문 대문자 1자 이상
- 영문 소문자 1자 이상
- 숫자 1자 이상
- 특수문자 1자 이상 (`!@#$%^&*` 등 프로젝트 허용목록)
- 공백 금지
- 비밀번호 확인 값 일치 필요
- DB에는 평문이 아닌 `password_hash`만 저장

## 공개 주문번호 정책
- 내부 PK인 order_id를 비회원에게 조회키로 사용하지 않는다.
- 모든 주문에 `order_no`를 발급한다. 예: `TM-20260917-A8K3Q7P2`.
- order_no는 UNIQUE이며 충돌 시 다시 생성한다.
- 비회원은 order_no 소유를 조회 권한으로 간주하는 학습용 범위다. 실제 상용 서비스라면 추가 인증이 필요하다.

## 반품 정책
- 구매가 완료되면 상태는 `CONFIRMED`.
- 전체 반품만 지원한다. 부분 반품은 제외한다.
- `CONFIRMED → RETURNED`만 허용한다.
- 반품 성공 시 `returned_at` 기록, 모든 품목 재고 복구.
- 시리얼 상품은 연결된 product_unit을 AVAILABLE로 복구하고 order_item_unit.returned_at을 기록한다.
- 동일 주문의 재반품으로 재고가 두 번 증가하지 않게 조건부 UPDATE를 사용한다.

## 공통 예외처리 원칙
1. 입력 형식 오류: DB 변경 전 차단하고 해당 항목 재입력.
2. 업무 규칙 위반: 중복, 재고 부족, 판매중지, 시리얼 부족, 권한 위반은 변경 없이 거절.
3. 트랜잭션 오류: 주문/반품/입고/회원가입 중 하나라도 실패하면 전체 rollback.
4. 조회 결과 없음과 DB 오류를 구분.
5. 사용자 화면에는 SQL/접속정보를 노출하지 않고, 개발 로그에 원인을 남긴다.
