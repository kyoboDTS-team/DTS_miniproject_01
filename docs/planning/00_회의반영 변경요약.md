# 터미널마켓 설계 변경 요약 v0.3

## 1. 회의 반영 핵심 변경

| 항목 | 이전안 | v0.3 결정 |
|---|---|---|
| 프로젝트 범위 | 문구점 중심 | 문구·완구·전자제품·명품을 취급하는 **터미널마켓** |
| 비로그인 | 로그인·종료만 가능 | 상품 조회, 장바구니, 비회원 구매, 주문번호 조회 가능 |
| 회원 생성 | 관리자가 고객 계정 생성 | **회원가입** 추가. 관리자는 회원 관리만 담당 |
| 로그인 ID | 일반 로그인 ID | **이메일 형식** + UNIQUE |
| 장바구니 | 없음 | 세션 메모리 장바구니. 헤더에 `장바구니(n)` 표시 |
| 주문 종료 상태 | 취소(CANCELLED) | **반품(RETURNED)** 으로 단순화 |
| 카테고리 | 문구 7개 평면 분류 | 하나의 category 테이블에서 상·하위 계층 |
| 시리얼 | 없음 | 시리얼 관리 상품만 product_unit으로 개별 관리 |
| 보류 | 없음 | 로그인 잠금, 추천인/포인트는 현재 스키마에서 제외 |

## 2. 테이블 수 결정
테이블은 9개로 조정한다. 테이블 수를 늘리는 것이 목적이 아니라 **독립적으로 식별·이력 관리가 필요한 사실만 분리**한다.

- app_user, customer: 계정과 고객 프로필 분리
- category: self FK로 상·하위 분류를 한 테이블에서 처리
- product, product_unit: 상품 모델과 개별 시리얼 단위 분리
- orders, order_item: 주문과 상품의 N:M 관계를 order_item이 연결
- order_item_unit: 주문 상세와 실제 시리얼 단위의 판매/반품 이력 연결
- stock_adjustment: 주문 외 입고·파손·수동 보정 이력

**장바구니는 DB 테이블을 만들지 않는다.** 프로그램 실행 중 세션 객체로만 유지한다. **반품 테이블도 만들지 않는다.** 전체 주문 반품만 지원하므로 orders.status와 returned_at으로 처리한다.

## 3. 보류 기능
- 로그인 실패 누적 잠금: 보류. `failed_login_count`, `locked_until` 컬럼을 아직 추가하지 않는다.
- 추천인 코드/포인트: 보류. 포인트·추천 관계 테이블을 아직 추가하지 않는다.

보류 기능을 구현하기로 확정할 때 별도 변경안으로 스키마를 확장한다.


## 4. 바로 반영할 작업 순서

| 순서 | 작업 | 주요 위치 | 완료 기준 |
|---|---|---|---|
| 1 | DB 스키마 | `sql/schema.sql`, `migrations/` | 9개 테이블, FK, UNIQUE, 상태값, NULL 정책 확정 |
| 2 | 초기 데이터 | `sql/seed.sql` | 상·하위 카테고리와 일반/시리얼 상품 테스트 데이터 |
| 3 | Java 공통 모델 | `auth`, `cart`, `product`, `order` | 이메일 ID, 장바구니, OrderStatus, ProductUnit 모델 일치 |
| 4 | 핵심 통합 흐름 | Main, 역할별 Menu, Service | 비회원 주문 → 회원가입/로그인 → 관리자 관리 흐름 연결 |
| 5 | 검증 기록 | `docs/test-cases.md` | T01~T22 실제 결과·오류·수정 내용 공동 기록 |

**우선순위:** 비회원 주문과 회원 주문을 먼저 연결한 뒤 시리얼·반품·통계·CSV를 붙인다. 보류 기능은 현재 작업 카드에 넣지 않는다.
